1. Systems should not be split into modules. Each module should instead hide one design decision that is likely to change. Parnas shows this with the KWIC index program. In his first design, each module is one processing step. Every module depends on how the lines are stored in memory, so changing that storage format means changing almost every module. Modules such as line storage and circular shifter hide their data format behind a small set of functions in Parnas’ second design. If the storage format changes, only one module needs to change.
This idea called information hiding, is still the basis of good design today. It is why classes keep their fields private and expose methods, and why REST APIs return data without revealing the database schema behind it. For example, libraries can change their internals without breaking the programs. The question Parnas tells us to ask, "what is likely to change, and which module should own that decision?", is still a useful way to decide where module boundaries go.

2.Parnas spends a lot of time on efficiency, and those concerns mostly no longer apply. He worries that his better design could be slower because every access goes through a procedure call, and calls were expensive on 1972 hardware. He suggest that a special tool might be needed to insert the code directly instead of calling it. He also treats it as a real design question whether all the lines can be kept in core at once and whether characters are packed four to a word.
Today compilers inline small functions automatically. This means the cost of calling a function like getChar is usually zero or close to it. Memory is also cheap enough that holding an entire text file in RAM isn’t necessary. This means the tradeoff Parnas had to defend, a cleaner design at the cost of speed, is rarely a tradeoff now. We can choose the information-hiding design almost by default.

3.In my data structures coursework I implemented data structures such as a linked list and a stack as Java classes. The node references and size counter were private, and other code could only use public methods like push, pop, peek, and isEmpty. The program that used the stack never touched the nodes directly.
This is the same idea as Parnas line storage module. Since the internal representation was hidden, I could have switched the stack from a linked list to an array without changing any of the code that used it. That change only affects the stack class, while changing the storage format in Parnas's second KWIC design only affects one module.
